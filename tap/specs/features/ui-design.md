# tap - UI / UX 设计说明

> 本文聚焦 **体验目标、信息架构与关键流程**。前端代码结构（Zustand store、IPC 边界、同步契约）见 `tap/AGENTS.md` 的“Frontend architecture”。

## 设计目标

tap 是一个“会执行你的手”的工具，UX 目标不是花哨，而是**可靠、可控、可预期、可恢复**。优先级：

1. **安全与可停止**：任何时候都能立刻停下（全局紧急停止、可视化状态、超时保护）。
2. **高信息密度但不压迫**：快速看清“将要做什么 / 正在做什么 / 为什么停了”。
3. **低门槛与可成长**：从“重复点击”起步，逐步引导到“录制 / 编辑 / 条件 / 参数化”。
4. **可维护**：UI 结构清晰、可替换，不把业务逻辑绑死在前端。

## 信息架构（IA）

“三栏 + 底部状态栏”结构：

```
┌──────────────────────────────────────────────────────────┐
│ Topbar: 当前宏 | 运行按钮 | 目标窗口 | 热键提示 | DRY RUN │
├───────────────┬───────────────────────────────┬──────────┤
│ 左栏: Profiles │ 中栏: Timeline Editor         │ 右栏:    │
│ - 最近使用      │ - List / Rail / Code 三视图    │ Inspector│
│ - 模板          │ - 动作卡片 / 时间轴 / YAML     │ - 坐标/键│
│ - 标签筛选      │                               │ - 目标窗口│
├───────────────┴───────────────────────────────┴──────────┤
│ Statusbar: 状态机 + 近期事件（可展开日志抽屉）            │
└──────────────────────────────────────────────────────────┘
```

顶层分 **Simple** 与 **Timeline** 两种工作模式：Simple 承载即时工具（重复点击 / 按键 / Key→Click），Timeline 承载录制 / 编辑 / 回放。

## 关键流程

### 首次使用（Onboarding）

目标：让用户 1 分钟内跑通一次“安全的重复点击”，并明确“如何停下来”。

1. 展示紧急停止热键（默认 `Ctrl+Shift+Backspace`）。
2. 引导选择目标窗口 / 屏幕区域（最简：倒计时 + 用户手动切窗口）。
3. 一键“加载示例宏”，进入时间线编辑器即可运行。
4. 明显位置展示运行态：Running 状态、下一步倒计时、已执行次数；并提示可选工具 Key→Click。

### 录制（Record）

必须“可控”：

- 三态按钮：Record / Pause / Stop。
- 显示录制时长、事件数（move/click/key）、降噪策略提示。
- Stop 后弹出“保存为宏”对话框：名称、标签、备注。

### 回放（Replay）

必须“可预期”：

- 开始前倒计时（允许切到目标窗口）。
- 带参数化变量的宏先弹**运行前变量表单**再倒计时。
- 运行时展示当前动作（高亮）、下一动作与剩余时间、当前/总循环（或 Forever）。
- 支持 Pause 与 Stop（终止回到 Idle）。

## 安全与可停止性（一等公民）

### 状态机

```
Idle → Arming → Running → Paused
  ↑        │        │        │
  └────────┴────────┴────────┘  (Stop / Emergency Stop)
```

### 必备机制

- **全局紧急停止**：无论窗口焦点都生效。
- **试运行（Dry run）**：仅记录不注入，顶栏 `DRY RUN` 徽标常驻提醒。
- **安全阈值**：连续注入失败 N 次自动停止；注入看门狗超时。
- **可恢复**：崩溃 / 异常后提示并可查看日志。

## 编辑器体验（Timeline Editor）

长期自用的核心竞争力是“编辑器舒服”：

- **三视图**：List（易读易改参数）、Rail（拖拽调时、理解节奏）、Code（YAML 源码 + 校验）。
- **动作卡片**：类型图标 + 关键参数（坐标/键/文本/延时）、启用/禁用开关、备注。
- **常用操作**：复制、上下移动、单步与批量调时（±50ms）。
- **Inspector**：编辑选中动作的全部参数与触发时间。

## 模板与复用

- 内置模板：Simple Click、Auto Type、Loop with Counter、Wait for Color 等（编译期内嵌，一键应用为新宏）。
- 参数化宏：把坐标/文本作为变量，运行前填入。
- 导入 / 导出：经原生文件对话框读写 YAML 宏文件。

## 权限与平台差异

- **macOS**：全局监听 / 输入注入需「辅助功能」，取色 / 像素 / 窗口标题需「屏幕录制」。需要权限引导页，以清晰可复制的步骤引导授予；权限缺失时禁用相应按钮并给出“去设置”入口与原因。
- **Windows**：目标应用可能是管理员权限；必要时提示“以管理员运行 tap”。

## 视觉风格

“工具型现代 UI”：深色为默认（高对比但不过亮）、清晰层级与间距、Running 状态突出但避免刺眼红色常驻。

## 全局坐标系统（UI 约束）

> tap 是全屏自动化工具，不是“窗口内”应用。所有鼠标坐标基于 OS 注入空间（Win 物理像素、mac point），而非 WebView 相对坐标（设计依据见 `functional-guide.md` 的“关键设计约束”）。

由此带来的 UI 约束：

1. **实时鼠标位置显示**：即使鼠标移出窗口也要显示全屏坐标——经后端全局事件获取，前端不依赖 DOM `mousemove`。
2. **坐标拾取器**：点击 “Pick” 后可点击屏幕任意位置（含窗口外）。实现为全屏透明覆盖窗口（半透明遮罩 + 十字准星 + 实时坐标），点击不穿透、ESC 取消。
3. **高 DPI**：进程启动设置 Per-Monitor V2 DPI Awareness；录制与回放使用同一物理像素坐标系。

**为什么不能用 DOM 事件**：WebView 的 `mousemove` / `click` 只能捕获窗口内部事件；鼠标移出或点击窗口外时收不到/打到别的应用。
