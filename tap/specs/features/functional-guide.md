# tap - 功能说明

## 概述

tap（Timed Action Performer）是一款桌面自动化工具，核心抽象是“按时间编排的一系列动作（Timed Actions）”。它从最简单的重复点击起步，逐步演进为可录制、可编辑、可回放、可条件化、可参数化的“宏（Macro）工作室”。

tap 不追求成为企业级 RPA，而是提供**轻量、低门槛、可持续扩展**的自动化能力，覆盖个人/小团队的重复性桌面操作。

## 产品原则

1. **可控优先**：永远有“停下来”的办法（紧急停止热键、清晰状态、超时/失败保护）。
2. **可预期优先**：用户随时知道“接下来会发生什么”。
3. **可恢复优先**：崩溃 / 权限缺失 / 目标窗口变化时，给出明确提示与恢复路径。
4. **从简单到强大**：能力按“重复 → 录制 → 编辑 → 条件 → 参数化 / 脚本 → 插件”逐级打开。
5. **跨平台一致**：Win 与 mac 提供一致操作模型，但把平台差异显式化（权限、热键、注入限制）。

## 目标用户与场景

- 需要频繁重复桌面操作的个人用户（游戏、运营、表单录入、测试回归等）。
- 想用“录制 + 小改动”快速做批处理的轻量自动化用户。
- 典型场景：定时重复点击 / 按键；录一段操作后一键重放；“打开应用 → 登录 → 点菜单 → 填表 → 保存”这类带条件与参数的流程。

## 核心概念

| 概念 | 含义 |
|------|------|
| **Action（动作）** | 最小执行单元：click / double-click、mouse down/up/move/drag/scroll、key tap/down/up、text input、wait、条件与计数器动作、`call_macro`、`exit`。 |
| **Timeline（时间线）** | 带相对时间（`at_ms`）的动作序列。tap 的核心是“把手的操作转换为可编辑的时间线，再由引擎稳定执行”。 |
| **Macro / Profile** | 一个宏：元数据（名称/描述/作者/标签）+ 变量 + 目标窗口绑定 + 时间线 + 执行策略。规范形态是 `MacroDocument`（无损），运行时解析为 `Profile`（坐标等解析为具体值）。 |
| **Variable（变量）** | `{{ name }}` 参数化占位；运行前由表单填入，或被表达式引用。 |
| **Condition（条件）** | 窗口聚焦/存在、像素颜色、计数器比较，以及 and/or/not 组合；用于 `wait_until` 与 `conditional` 分支。 |
| **Tool Mode（工具模式）** | 由实时全局输入驱动、不在时间线上的能力（如 Key→Click）。**不属于 DSL**，不能用 YAML 表达。 |

## 功能能力

### 1. 简单工具（Simple）

“最小闭环”的即时能力，无需编排时间线：

- **固定坐标点击**：设置 x/y 与鼠标按键（左/右/中），间隔 N ms 循环执行；坐标可用 Pick 拾取。
- **按键重复**：设置键位（支持 “Capture” 按钮录入下一次实际按下的键），间隔 N ms 重复。
- **Key→Click（键盘连点替代鼠标连点）**：开启后按住 `A`–`Z` 任意键即可持续模拟鼠标点击（轻点=单击，按住超过 hold delay 后以最小间隔连点）；`Space` 立即终止。可配置：鼠标按键、点击位置（跟随光标 / 固定坐标）、最小间隔（限频 10–1000ms）、以及“仅在启动时活动窗口内点击”（按进程名锁定，alt-tab 离开即暂停）。详见 [Key→Click](./key-to-click-mode.md)。

### 2. 录制（Record）

- 记录鼠标移动 / 点击 / 滚轮 / 键盘按键，附带时间戳用于回放节奏。
- 录制可暂停 / 继续。
- 结束时自动**降噪合成**：合并共线鼠标移动、把按下/抬起合成为 `Click` / `DoubleClick` / `Drag`、把按键合成为 `KeyTap`（可在配置中关闭，保留原始事件）。
- 录制得到的平台按键名在入库前即**归一化**为规范名（见“关键设计约束”）。

### 3. 编辑（Edit）

时间线编辑器提供三视图 + 参数检查器：

- **List 视图**：增 / 插 / 删 / 上下移 / 复制，单步 ±50ms 调时，启用/禁用，显示备注。
- **Rail 视图**：按时间排布的轨道，拖拽标记即可调时。
- **Code 视图**：YAML 源码编辑（含校验与错误定位）；带变量/表达式的参数化宏在此编辑，避免被“解析视图”压平。
- **Inspector**：编辑选中动作的类型、坐标/按键/文本、触发时间与备注。
- **批量调时**：整条时间线统一 +50ms / -50ms。

> **编辑即落库**：可视化编辑去抖回推到后端规范文档（`MacroDocument`），并在“开始 / 保存”前强制刷盘，因此保存或回放始终反映最新编辑——结构上杜绝“改了没生效”。参数化宏的可视化视图为只读（重推会压平参数），改其参数请用 Code 视图。

### 4. 回放（Replay）

- 按时间线执行，支持倍速（0.5x / 1x / 2x）与循环 N 次（0 = 永久）。
- 支持“开始前倒计时”（子秒级），方便切到目标窗口。
- **运行前变量表单**：当宏带参数化变量时，点击开始会先弹表单收集运行时取值（覆盖默认值），填好后才进入倒计时并执行。

### 5. 条件与编排

- **窗口绑定**：宏绑定到特定窗口（标题/进程名），运行时校验；不匹配则按配置暂停并提示。
- **像素颜色检测**：检测某坐标颜色是否匹配（RGB 容差）。
- **分支与等待**：`conditional` 实现 if/else，`wait_until` 等待条件满足（带超时与轮询间隔）。
- **变量与计数器**：set/incr/decr/reset，用于循环控制与退出条件。

### 6. 参数化与脚本

- **YAML DSL**：宏可完整用 YAML 描述，便于版本管理、分享与批量修改。详见 [DSL 参考](./dsl-reference.md)。
- **参数化变量**：`{{ var }}` 占位 + 运行前表单。
- **内嵌轻表达式**：`{{ counter + 1 }}`、`{{ "prefix_" + name }}`，Rhai 沙箱执行（禁用文件/网络，限制深度与操作数）。
- **子宏调用 `call_macro`**：按名加载并就地展开另一段宏；独立子作用域、环/深度（≤10）保护、子宏 `exit` 只结束自身。

### 7. 持久化与素材

- **保存 / 加载 / 删除**：规范文档以 YAML 落盘（`MacroDocument`，无损往返）。
- **无损元数据编辑**：描述 / 作者 / 标签独立写入，即使参数化宏也不会压平参数。
- **最近使用**：最近打开 / 保存的宏列表，可一键加载。
- **内置模板**：随应用编译期内嵌的示例宏，可浏览并一键应用为新宏（见 `tap/templates/`）。
- **原生导入 / 导出**：经系统原生文件对话框选择路径，导入 / 导出 YAML 宏文件。

### 8. 权限检测与首次引导

- **权限探测**：启动时与窗口重新聚焦时主动探测 OS 权限，避免“静默失败”。
  - macOS：检测「辅助功能」（录制 / 回放 / Key→Click 必需）与「屏幕录制」（取色 / 像素条件 / 窗口标题必需）。缺失时主区域顶部显示横幅，提供「打开系统设置」「请求屏幕录制」「重新检测」；辅助功能未授予时直接禁用录制 / 回放 / Key→Click 并给出提示。
  - Windows：信息横幅提示“若目标程序以管理员身份运行，tap 也需以管理员身份运行”（可忽略，本机记忆）。
- **首次引导**：首启展示欢迎横幅，说明紧急停止热键，并提供「加载示例宏」一键进入时间线编辑器（本机记忆，忽略后不再出现）。

### 9. 安全与可观测

- **全局紧急停止**：热键 `Ctrl+Shift+Backspace` 最高优先级，无论窗口焦点都立即停止。
- **试运行（Dry run）**：开启后引擎与 Key→Click 仅记录不真正注入，可零风险预演；顶栏显示 `DRY RUN` 徽标。
- **卡死保护**：注入看门狗超时、连续注入失败自动停止；拖拽按时长可中断插值，异常时必定抬起按键，避免鼠标卡在按下态。
- **可观测**：执行可视化（当前/下一步动作 + 剩余时间 + 已执行次数）、近期事件日志面板、错误提示（权限不足、Hook 失败、注入失败等）。

## 关键设计约束（需长期记住）

1. **坐标系 = 注入空间**：所有鼠标坐标基于 OS 注入空间——**Windows 全屏物理像素**、**macOS point**，绝不使用 WebView 相对坐标。拾取器经 `browser_to_injection_scale()` 把浏览器 CSS 像素换算到注入空间，使录制 / 回放 / 拾取三者一致；`get_primary_scale_factor()` 仅作信息展示。**因此宏不跨机移植**，换机需重新拾取坐标。
2. **按键名归一化**：录制 / 捕获得到的平台按键名（`ControlLeft` / `ShiftLeft` / `MetaLeft` / `AltGr` / `Return` / `Kp5` …）在入库与注入前统一归一化为规范名（`Ctrl` / `Shift` / `Meta` / `Enter` / `5` …），避免修饰键被误当字母键注入，并保证同一宏可在 Win/mac 间移植回放。
3. **工具模式 vs DSL**：事件驱动的工具模式（Key→Click）由实时输入驱动、时长不定，刻意不塞进时间线 DSL，避免引擎复杂化。它属于 Application/Tauri 层的 Tool Runner。
4. **单一数据源**：规范宏是 `SessionStore` 持有的 `MacroDocument`；运行时 `Profile` 只是用于展示/IPC 的解析投影。编辑与执行始终经由文档，绝不走有损副本。
5. **串行执行**：单个宏内动作顺序执行，无并发注入。
6. **可取消**：所有长耗时操作（回放、录制、拖拽插值）必须支持经停止信号立即取消。

## 非目标

- 企业级 RPA：复杂流程编排、流程监控、集中管理。
- 通用跨设备自动化：移动端自动化（另起项目）。
- 过度侵入式“反检测”：tap 以合法、用户自用为前提。

## 风险与注意事项

1. **权限与安全**：全局输入 Hook / 输入模拟在不同 OS 有权限要求（macOS 辅助功能）。mac 的窗口枚举与像素取色基于 Quartz（`CGWindowList`），读取窗口**标题**与**像素颜色**还需“屏幕录制”权限，缺失时按进程名匹配仍可用。应用在启动与重新聚焦时探测权限并在横幅引导授予、权限不足时禁用相应操作。
2. **目标变化**：目标应用更新 UI / 分辨率变化会导致坐标偏移；相对坐标 / ROI / 校验是降低维护成本的方向（见 backlog）。
3. **录制噪声**：move 事件量极大，已用抽样限频 + 共线合并 + 高层动作合成压缩。
