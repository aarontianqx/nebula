# 状态帧序列矩阵

宠物身份的单一事实源是主人原狗照片及确认过的标准 reference。动画使用三种表达：单一标准姿势加程序微动画、少量语义关键姿势、以及确实需要连续肢体运动的短帧序列。旧 4×4 宫格保留为迁移来源，不再要求所有状态播放全部 16 帧。

> 历史：Phase 1 曾用单张 4×4 宫格（每状态 1 帧 + 程序化晃动）与 Live2D 待机方案；Phase 2 初版为 9/4 帧混合，后升级 25 帧（5×5 + 超分 + RIFE 插帧）。25 帧版因 AI 生成帧非连续动作反而加剧跳变、且分辨率摊薄，回退为 16 帧方案：帧少但每帧是完整连续动作相位，连贯性由生成质量而非后处理保证。

## 状态定义

`src/pet/assets.ts` 是运行时选帧与时间参数的事实源。

| 状态 id | 动画内容 | 触发条件 | 播放 fps |
|---------|----------|----------|----------|
| `idle` | 标准正面底图 + 局部眨眼 + 呼吸/探头 | 默认 | 程序化 |
| `walk` | 经闭环筛选的 6 帧侧面步态 | 随机走动 + 窗口位移 | 10 |
| `run` | 经闭环筛选的 4 帧 gallop | 随机走动（25% 概率，位移更快更远） | 12 |
| `cheer` | 6 个语义关键姿势，可变停留 | 番茄钟完成 / 饮水确认 | 关键帧 |
| `stretch` | 下犬式伸懒腰 + 打哈欠 + 抖毛全过程 | 待机轮换 | 8 |
| `petted` | 4 个原狗关键姿势往返 + 程序爱心 | 点击 / 拖拽落地 | 关键帧 |
| `sleep` | 标准蜷缩姿势 + 呼吸 + 程序 Zzz | 待机轮换 | 程序化 |
| `rest` | 标准趴卧姿势 + 慢呼吸 | 待机轮换 / 番茄钟休息期 | 程序化 |
| `drink` | 舔水循环 + 抬头吞咽 + 舔嘴唇 | 喝水提醒触发（常驻至点击确认） | 8 |
| `focus` | idle 标准底图 + 局部眨眼 + 程序眼镜 | 番茄钟专注中 | 程序化 |
| `tired` | 标准疲惫姿势 + 慢呼吸 | CPU 高负载 / 低电量 | 程序化 |
| `sulk` | 标准委屈姿势 | 久未互动 | 程序化 |
| `greet` | 6 个语义挥手关键姿势 | 应用启动 | 关键帧 |
| `curious` | 标准姿势 + 程序歪头和问号 | 待机轮换 | 程序化 |
| `grabbed` | 被拎悬空：钟摆晃动 + 蹬腿挣扎 | 拖拽中 | 8 |

## 资产规格与生成管线

1. **参考与生成**：主人原狗照片及 `assets-src/live2d/parts/reference.png` 是角色身份基准。新增资产每次只生成一个语义关键姿势，纯 chroma-key 背景，不直接生成整张动作宫格。`scripts/imagegen_url.py` 兼容返回签名 URL 的 Images API，并把非敏感生成参数写入同名 metadata。
2. **拒绝标准**：即使单帧美观，只要眼距、口鼻、头身比、腿长、爪子、毛色或四肢拓扑相对 reference 漂移，就拒绝该批生成图。大幅姿态改变无法保持身份时，复用已验收旧帧并减少关键姿势数量。
3. **旧宫格迁移**：现有 `assets-src/frames/*_grid_4x4.png` 仍是连续动作的来源。`scripts/slice_frames.py` 负责：
   - 格子内缩 1.2%（裁掉格线）；
   - 背景去除：白底判定 → 边界连通 = 背景 → 封闭白洞剔除（保留眼睛高光）→ 白底去污染反解前景色 + 软边缘；
   - 去噪：保留最大连通域（本体）+ 不触边的装饰（爱心/Zzz/问号）；细线与低填充率碎片（格线残留）剔除；
   - **锚点对齐**（防错位关键）：逐帧以本体（质心 x，脚底 y）为锚点平移对齐，消除 AI 宫格随机漂移；空中动作（run/cheer/grabbed）只做水平对齐，纵向位移是真实动画相位；
   - 触边告警：前景贴格子边 = 截断风险；petted/grabbed 的顶部触边（手/后颈毛刻意出格）为预期白名单，不告警；
   - 状态级共用裁剪窗口：对齐后各帧 bbox 并集统一裁剪 → 同状态所有帧同尺寸，播放零错位；
   - 体型归一化：以 idle 前景面积为基准输出缩放系数到 `manifest.json`；
   - 末段自动 `pngquant --quality=75-92` 有损量化，240 帧总体积 ~6.2MB（`--no-quant` 跳过）。
4. **动态验收**：`scripts/validate_animation.py` 按实际 FPS/停留时间生成 GIF，并输出面积变异、锚点范围、相邻帧差异和首尾差异。`preview_frames.py` 的联络表只用于定位单帧问题，不能单独作为连贯性放行依据。

## 渲染端防裁切与尺寸

- 画布 200×190（窗口 210×200）；idle 站姿高度占画布 85%（约 160 逻辑 px），其余状态按体型归一化系数缩放。
- **fit 保护**（`PetCanvas`）：任何状态缩放后仍超出画布时整体再缩，确保削头/断尾不可能出现。

## 与状态机的关系

- 常驻状态优先级：饮水提醒 > 番茄钟阶段 > 系统高压 > 待机；临时状态（petted/cheer/greet）播完一轮回落（`hooks/usePetStateMachine.ts` 的 `PetController`）。
- 每状态 fps 与资产表见 `src/pet/assets.ts`；待机轮换池（含权重）见 `src/pet/behavior.ts`；走动/奔跑调度见 `src/hooks/useIdleBehavior.ts`。
- 走动 = walk/run 帧循环 + 窗口水平位移（`src/features/walker.ts`）；到达目标点回落常驻状态。

## 资产变更 checklist

1. 用原狗 reference 生成单个低质量关键姿势草稿，检查身份；不要先生成整批。
2. 身份通过后再生成其余相邻姿势，每一张同时提供 reference 和动作约束。
3. 用 chroma-key helper 去背，检查透明四角、主体覆盖和毛发绿边。
4. 在 `src/pet/assets.ts` 声明表达类型、选帧和时间，不强求固定帧数。
5. 跑 `scripts/validate_animation.py {state}`，至少观察三个正常速度循环，并以慢速检查脸、四肢、耳朵、尾巴和道具。
6. 对旧宫格返工时再运行 `slice_frames.py` 和 `preview_frames.py`，同时仍需执行动态验收。
